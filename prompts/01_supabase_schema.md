# 01 — Supabase schema, RLS and RPC

Read `docs/ARCHITECTURE.md` §4–5 and `docs/GAME_RULES.md` §1, §3, §6, §7.

## Goal
The full database: tables, enums, RLS policies, read views and the lobby + squad + order RPC
functions, with tests proving the security table of ARCHITECTURE §5.

## Do
1. Plan first: list migrations, policies and RPC signatures. Wait for my OK.
2. Migrations for every table of §4. Players are `league_members.member_id` (the Drone is
   a member with no `user_id`). Separate `market_runs` (global) and `job_runs` (per league,
   `league_id` not null). Phase timestamps on `weeks`. No column named `window`.
3. `seed.sql` generated by a script in `supabase/scripts/` from `data/instruments.csv`
   (sector codes) and from `engine/config.py` for `game_config`. Do not hand-type rows.
   Add a test that fails if `game_config` differs from `engine/config.py`.
4. RLS: enable on every table. No client INSERT/UPDATE/DELETE on game tables.
5. RPC (`security definer`, `set search_path = ''`, schema-qualified names):
   `create_league`, `join_league`, `leave_league` (lobby only), `update_member`,
   `set_ready`, `start_campaign`, `set_locale`, `save_squad`, `swap_unit`, `cancel_swap`,
   `play_order`, `propose_pact`, `accept_pact`, `decline_pact`. Each checks auth,
   membership, the deadline (`now()` against the `weeks` timestamps, never `phase` alone)
   and the rules, reading every value from `game_config`:
   2 EU / 2 US, veteran region, conflict zone, unique instrument, reserve composition,
   swap count (1, Quartermaster 2) and squad validity after swaps, Blockade,
   ammo balance and cost incl. Bounty discount, attack cap of 2, once-per-week orders,
   Berserker restrictions, Shadow immune to intel, one active pact per week.
   `intel` resolves immediately: it writes a snapshot event for the attacker only.
   Return errors as stable codes (e.g. `SQUAD_NEEDS_2_EU`) with variables; the UI
   translates them (EN/FR). Add `profiles.locale`.
6. Views: `orders_public`, `squads_visible`, `ammo_balance` — `security_invoker = true`
   unless the view must mask data, in which case it filters on membership itself.
   `scores_live_public` is a **table** written masked by the job (Realtime cannot watch
   views). Internal helpers in a `private` schema; `revoke execute … from public, anon`
   on every function, explicit grants for player RPCs only.
7. Tests in `supabase/tests/`: for each row of ARCHITECTURE §5, prove what player A,
   player B and an outsider can and cannot read; for each RPC, one success and every
   rejection path, including a call after its deadline while `weeks.phase` is stale;
   list every function `anon` can execute.

## Acceptance
- `supabase db reset` (local) or a fresh dev project applies everything without errors.
- All tests pass. Show me the RLS matrix as a table of test names → result.
- List anything in the rules you could not enforce in SQL and how you propose to handle it.
